# SAT-SA Data Requirements & Schemas

The SAT-SA pipeline ingests organizational telemetry via CSV or JSON formats. All data uploaded via the web interface must adhere to the schemas documented below.

## 1. Entities
Describes the organizational entities (CSEs) being monitored.

| Field | Type | Required | Description | Example |
|-------|------|----------|-------------|---------|
| `entity_id` | String | YES | Unique identifier | `CSE-001` |
| `entity_name` | String | YES | Human-readable name | `National Bank` |
| `sector` | String | YES | Industry cohort | `Finance` |

## 2. Assets
Describes the critical infrastructure assets within an entity.

| Field | Type | Required | Description | Example |
|-------|------|----------|-------------|---------|
| `asset_id` | String | YES | Unique identifier | `AST-001` |
| `entity_id` | String | YES | Parent entity | `CSE-001` |
| `asset_type` | String | YES | System classification | `SERVER` |
| `criticality` | Enum | YES | `LOW, MEDIUM, HIGH, CRITICAL` | `CRITICAL` |
| `expected_telemetry`| String | YES | Expected reporting frequency | `1 hour` |
| `last_telemetry` | ISO Date | NO | Last successful heartbeat | `2026-09-28T12:00:00Z` |

## 3. Alerts
Describes security alerts generated by SIEM/IDS systems on assets.

| Field | Type | Required | Description | Example |
|-------|------|----------|-------------|---------|
| `alert_id` | String | YES | Unique identifier | `ALT-001` |
| `timestamp` | ISO Date | YES | Time of occurrence | `2026-09-28T10:00:00Z` |
| `entity_id` | String | YES | Parent entity | `CSE-001` |
| `asset_id` | String | YES | Affected asset | `AST-001` |
| `severity` | Enum | YES | `LOW, MEDIUM, HIGH, CRITICAL` | `HIGH` |
| `category` | String | YES | Attack vector / type | `MALWARE` |
| `status` | Enum | YES | `OPEN, CLOSED, ESCALATED` | `CLOSED` |

## 4. Cases
Describes investigations mapping to escalated alerts.

| Field | Type | Required | Description | Example |
|-------|------|----------|-------------|---------|
| `case_id` | String | YES | Unique identifier | `CAS-001` |
| `alert_id` | String | YES | Parent alert | `ALT-001` |
| `entity_id` | String | YES | Parent entity | `CSE-001` |
| `investigator`| String | YES | Assigned analyst | `SOC-01` |
| `opened_at` | ISO Date | YES | Investigation start | `2026-09-28T10:05:00Z` |
| `investigation_duration`| Float | YES | Time spent in minutes | `15.5` |
| `escalated` | Integer | YES | `1` (true) or `0` (false) | `0` |
| `closure_reason`| String | NO | Remediation notes | `False Positive` |
| `remediation_status`| Enum | NO | `None, In Progress, Completed` | `None` |

## 5. Expert Finding Labels (Validation)
Used solely for precision/recall validation of system findings against independent human ground truth. Do not create these rows from SAT-SA predictions.

| Field | Type | Required | Description | Example |
|-------|------|----------|-------------|---------|
| `finding_id` | String | YES | Existing SAT-SA finding under review | `EG-FAST-CSE-007` |
| `entity_id` | String | YES | Entity belonging to the finding | `CSE-007` |
| `expert_label` | Enum | YES | `CONFIRMED` or `NOT_CONFIRMED` | `CONFIRMED` |
| `reviewer_id` | String | YES | Human reviewer identifier | `reviewer-01` |
| `review_timestamp` | ISO Date | YES | Time of independent review | `2026-09-28T10:00:00Z` |
| `rationale` | String | NO | Human review rationale | `Evidence supports the finding` |

## Expert validation template

`data/expert_validation_template.csv` contains headers only. It is not populated with labels. The system rejects unknown findings, mismatched entities, invalid labels, missing reviewers, invalid timestamps, and duplicate rows.

## Header Aliasing
The system supports automatic column mapping for common aliases (e.g., `alertId` or `alert identifier` will automatically map to `alert_id`). However, adhering strictly to the internal schema above guarantees optimal ingestion.
